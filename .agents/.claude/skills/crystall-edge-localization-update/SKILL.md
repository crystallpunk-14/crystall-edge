# Обновление локализации CE (crystall-edge-localization-update)

Имена, описания и суффиксы сущностей CE переводятся не руками "с нуля", а скриптом `Tools/_CE/LocalizationHelper`: он читает YAML из `Resources/Prototypes/_CE/`, сливает со старым `entities.ftl` (сохраняя русские строки) и пишет новый файл. Наша задача - прогнать его, аккуратно перевести появившиеся английские строки и не сломать уже сделанный перевод.

Скилл работает в цикле: **прогон -> пакеты по ~100 строк с ревью пользователя -> проверка -> синхронизация result.json**. Пользователь ревьюит каждый пакет, поэтому не переходи к следующему без его ответа.

Скрипты скилла: `.claude/skills/crystall-edge-localization-update/scripts/translate_batch.py` (ниже `$B`). Запускай из корня репозитория: `python .claude/skills/crystall-edge-localization-update/scripts/translate_batch.py <команда>`.

## Шаг 1. Прогон инструмента

1. Убедись, что `Tools/_CE/LocalizationHelper/last_launch_result/result.json` не изменён (`git status`). Он - "снимок YAML прошлого прогона", по нему инструмент понимает, что изменилось.
2. Из папки инструмента: `python main.py` (нужны Python 3.10+ и `pip install -r requirements.txt`). Рядом появится `entities.ftl`.
3. Быстро проверь результат до копирования: файл должен содержать кириллицу. Если весь файл английский - старый `.ftl` не прочитался
4. Скопируй `entities.ftl` поверх `Resources/Locale/ru-RU/_CE/_PROTO/entities.ftl` и удали временный файл из папки инструмента.
5. Сверься с `git diff --stat`. Прогон мог откатить переводы - проверь, что русские строки на месте (например, что в новом файле сохранилось большинство кириллицы). Если переводы пропали - это баг инструмента, чини его (см. "Известные грабли"), а не переводи заново. Откат: `git checkout -- <ftl> <result.json>` и повторный прогон.

## Шаг 2. Цикл пакетного перевода

Повторяй, пока `next` не вернёт `pending 0`:

1. `$B next 100` - печатает до 100 непереведённых полей в формате `Id.name = English` / `Id.desc = English` и сохраняет их. Скрипт уже пропускает: ссылки `{ ent-X }`, `{ "" }`, суффиксы, `TODO`-описания, строки без букв, названия эссенций (`CEEssence*`) и кубики - их не переводим.
2. Если `next` сообщил `exact-match hits` (совпадения с уже переведёнными строками из памяти переводов) - применяй `tm_hits.txt` тем же `apply` после беглого просмотра. Скрипт сам не подставляет их, потому что чужой перевод бывает неуместен.
3. Переведи пакет. Запиши перевод в файл рабочей папки (путь печатает `next`, обычно `%TEMP%\ce_loc_batch\batch_ru.txt`) инструментом Write - строго формат `Id.field = русский текст`, одна строка на поле. Пиши кириллицу только через Write/Edit, не через Bash/echo: Bash-обёртка ломается на кириллице.
4. `$B apply <файл>` - применяет пакет, отказывает при битых символах (U+FFFD) и сообщает `NOT FOUND` для лишних ключей.
5. Покажи пользователю итог: сколько применено, сколько осталось, и **список спорных мест** (придуманные термины, склонения, шутки, дословно переданные странности оригинала). Спроси правки.
6. Правки пользователя вноси через Edit прямо в `entities.ftl` (не перезапуская пакет), проверь, что соседние слова согласованы (род, падеж). Новые термины и предпочтения дописывай в память как глоссарий, чтобы не терять их между пакетами.

Пользователь может править **английский исходник в YAML** (переформулировать описание, убрать слово "shift", поменять число монет). Тогда обнови и русскую строку, и запомни, что эту сущность нужно синхронизировать в result.json (Шаг 4).

## Шаг 3. Проверка

`$B check` - должно быть: `dangling refs 0`, `U+FFFD 0`, `= None 0`, `entries without .desc 0`. Остаток `TODO placeholders` - норма: у этих сущностей в YAML описание "TODO", придумать его должен разработчик; перечисли их пользователю.

Попроси запустить клиент на русском и прислать ошибки лога `loc:`. Типичное: `No value: ent-X.desc` (запись без `.desc`), пустые/`None` названия.

## Шаг 4. Обязательное завершение: синхронизировать result.json

`$B sync-result --dry-run` покажет, какие сущности расходятся с YAML; затем `$B sync-result` перезапишет `last_launch_result/result.json` текущим состоянием YAML.

Зачем: инструмент сравнивает YAML с result.json, и любое поле, изменившееся в YAML после прошлого прогона, при следующем запуске перезаписывается английским текстом, затирая русский перевод. Правки английского в YAML в ходе сессии (или родителя/суффикса) без синхронизации приводят к тихой потере переводов. Делай синхронизацию в самом конце, а также сразу после любой правки английского текста в YAML. Коммитить `result.json` нужно вместе с `entities.ftl`.

## Правила перевода

Смысл: игра фэнтезийная, язык живой, тон как у оригинала (шутки сохраняй, но не выдумывай смысл).

- Названия сущностей - со строчной буквы, как в существующем файле (`очки`, `меховой плащ`). Действия и цели ролей - с заглавной.
- Не переводим: `.suffix`, названия эссенций (Terra, Ignis, Aqua, Aer, Ordo, Perditio и т.п.), `TODO`-описания, кубики `d20`/`d6`.
- Нет "смен": это не станция, а неделя в городе. Не пиши "за смену", "эту смену".
- Названия рас берём из `Resources/Locale/ru-RU/_CE/species/species.ftl`: человек, тифлинг, дварф, эльф, гоблин, сильва, каркат, скелет, каррин; ещё: флем, люмигриб, миконид.
- Термины: мрак (murk), световой монолит, пилон, Сфера Люксона, нода (node), сбой (mishap), тауматург/тауматургия, эссенция, мана, **луркер** (не "скрытень"), **для админов** (не "для администраторов"), **алтарь слияния** (не "инфузии"), **тауманомикон**, бола (жен. р.), "воздушная ловушка" (AirCaught).
- Если пользователь поправил термин - обнови этот список в памяти/скилле.
- Перед переводом сверяйся с существующими русскими строками (grep по `Resources/Locale/ru-RU/_CE`), чтобы термины не расходились.

## Известные грабли инструмента (уже исправлены, но проверяй при аномалиях)

- Путь `FTL_FILES_PATH` в `main.py` - папка `_PROTO`, иначе все переводы теряются.
- Пустые имя/описание пишутся как `{ "" }`, никогда `None`; у каждой записи обязателен `.desc`; записи без имени, описания и суффикса не пишутся вовсе. Явная пустая запись перекрывает локализацию родителя из движка.
- Обновляются только атрибуты, изменившиеся в YAML с прошлого прогона (иначе смена `parent` затирает переводы).
- Родитель, который сам задан списком `parent: [...]`, должен считаться существующим (иначе у наследников пропадают имя и описание).
- Автоперенос по памяти переводов не должен использовать `TODO` как источник.

Если инструмент ведёт себя странно - чини причину в `Tools/_CE/LocalizationHelper` (не подменяй руками результат), откатывай сгенерированные файлы и прогоняй заново.
