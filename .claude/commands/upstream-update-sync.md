# upstream-update-sync

CE больше не мержит апстрим целиком — только черри-пикает отдельные PR. `git merge-base` поэтому навсегда застрял на последнем полном синке, и что уже просмотрено, знает только **журнал**:

`G:\Мой диск\CrystallEdge\upstream-ledger.md` (в Git Bash: `/g/Мой диск/CrystallEdge/upstream-ledger.md`)

В журнале **курсор** (SHA `upstream/stable`, до которого всё просмотрено) и таблица вердиктов по PR. Журнал вне репо — не коммитится.

## Что CE полезно

CE не использует контент апстрима: свои текстуры, прототипы и карты в `_CE`. Апстримный контент (аномалии, зомби, антаги, ботаника, станционные отделы) вырезается. Реюзаются **кор-механики** (движение, инвентарь, руки, взаимодействия, DoAfter, UI, физика, атмос-ядро, предикт, админка, сеть, БД) и **звуки**.

Полезный PR: фикс бага/эксплоита, перф, предикт или рефактор в кор-системе, которая у нас жива; фикс звуков. Не полезный: новый контент, спрайты, карты, баланс апстримных предметов, системы, которые у нас вырезаны или заменены своей `_CE`-версией (например, мили — у нас свой CEWeapon).

## Шаги

1. **Курсор.** Прочитай журнал, возьми SHA из строки `Cursor:`. Журнала нет или строка пустая — остановись и спроси пользователя; курсор не угадывать.

2. **Fetch.**
   ```bash
   git fetch upstream stable && git rev-parse --short upstream/stable
   ```
   Запомни этот SHA — это будущий курсор. Совпадает с текущим курсором — новых PR нет, сообщи и закончи (вернись к шагу 3 только ради строк `later`).

3. **Триаж скриптом.**
   ```bash
   bash .claude/commands/upstream-update-sync.sh <cursor>
   ```
   Корзины (первая колонка):
   - `code` — трогает живые у нас C#/XAML/прототипы/звуки; колонка `N/M` = сколько из затронутых файлов у нас есть. Читать.
   - `engine` — бамп RobustToolbox: сравни с нашим `git -C RobustToolbox describe --tags`.
   - `gone` — все затронутые файлы у нас вырезаны. Пропуск без чтения.
   - `assets` — только текстуры/карты/локаль/доки. Пропуск без чтения.
   - `picked` — номер PR уже есть в нашей истории. Пропуск.

   Плюс все строки журнала с вердиктом `later` — их проверь заново (вдруг вышел фикс или изменились обстоятельства).

4. **Чтение PR.** По каждому `code`, `engine` и `later`:
   ```bash
   gh pr view <N> -R space-wizards/space-station-14 --json title,body,files
   ```
   Посмотри затронутые файлы у нас: жива ли система, нет ли `_CE`-замены, применяется ли патч (`git show <sha> > /tmp/p.patch && git apply --check /tmp/p.patch`). Готово, когда у каждого такого PR есть вердикт и причина в одну строку.

5. **Отчёт.** Таблица пользователю, полезное сверху:

   | PR | Вердикт | Причина | Патч |
   |----|---------|---------|------|

   Вердикты: `take` (стоит черри-пикнуть), `later` (интересно, но рано/ждём), `skip`. Ниже одной строкой — сколько ушло в `gone`/`assets`/`picked`. Черри-пик не делать — только отчёт; пользователь сам решит.

6. **Журнал.** После того как пользователь согласился с вердиктами (или поправил их):
   - допиши строки `code`/`engine`/`later` в таблицу (вердикт `later` обнови на месте, а не дублируй);
   - замени `Cursor:` на SHA из шага 2 и сегодняшнюю дату.

   Курсор двигается только на этом шаге: оборванный на середине скан просто повторится.
